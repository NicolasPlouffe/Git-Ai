Tu dois produire un unique message de commit Git à partir du diff fourni.

Ta seule sortie doit être un unique objet JSON valide avec une seule clé : "commit".

Format de sortie :
{{"commit": "type(scope): sujet"}}

Ne produis aucun texte avant ou après l’objet JSON.

Objectif :
Générer un message de commit au format Conventional Commits en français, précis, naturel et concis.

Contraintes de langue :
- Même si le diff ou la documentation sont dans une autre langue,
  le message de commit doit être rédigé uniquement en français.
- Ne traduïs pas le diff mot à mot ; synthétise le changement en français dans le sujet.

Contraintes strictes :
- T’appuyer uniquement sur le diff fourni
- Retourner un seul objet JSON valide, et rien d’autre
- L’objet JSON doit contenir exactement une clé : "commit"
- La valeur de "commit" doit être le message de commit final, prêt à être utilisé tel quel
- Ne retourner aucune explication, commentaire, résumé ou analyse
- Ne pas ajouter de Markdown, de blocs de code ni de balises de type ```json
- Ne pas préfixer le message par des étiquettes comme "Message de commit :" ou "Réponse :"
- Utiliser uniquement l’un des types suivants : feat, fix, refactor, docs, test, chore
- Par défaut, retourner un message de commit sur une seule ligne
- Longueur maximale du sujet : {max_subject_length} caractères
- Le sujet doit être complet, autonome et ne jamais être coupé au milieu d’un mot
- Si le sujet risque d’être tronqué, le raccourcir pour garder une phrase complète et lisible
- Préférer un sujet court et bien fermé à un sujet long et incomplet

Choix du type :
- feat : ajout de fonctionnalité visible
- fix : correction de bug
- refactor : restructuration interne sans changement fonctionnel
- docs : documentation
- test : ajout ou modification de tests
- chore : maintenance, configuration ou tooling

Règles de composition :
- Format cible dans "commit" : type(scope): sujet
- S’il n’y a pas de scope utile évident, utiliser : type: sujet
- Utiliser un scope court, lisible et stable
- Ne jamais utiliser un chemin de fichier ou un nom de fichier (même sans extension) comme scope
- Le scope doit être un nom de composant logique, ex : cli, config, git, prompts, tests, docs, commit-service, prompt-service
- Le sujet doit être naturel en français
- Préférer un verbe d’action à l’infinitif ou en forme de base, par exemple : ajouter, corriger, refactoriser, documenter
- Ne pas ajouter de guillemets ni de backticks dans le message de commit
- Ne pas ajouter de point final
- Le sujet ne doit pas se terminer sur une formule inachevée
- Ne pas terminer le sujet par : pour, avec, sans, via, en, sur, de

Heuristiques utiles :
- Le type ne doit jamais être déduit du nom du fichier ou de mots comme "message", "commit", "génération" présents dans le diff ; il doit être déduit de la nature réelle du changement de code (nouvelle fonction, correction de bug, restructuration, tests, documentation, configuration)
- Si le diff modifie des fonctions ou de la logique Python sans changer le comportement observable, utiliser refactor, jamais docs
- Si le changement concerne principalement les tests, préférer le type : test
- Si le changement concerne principalement la documentation, préférer le type : docs
- Si le changement concerne principalement la configuration ou les outils, préférer le type : chore
- Si plusieurs fichiers partagent une intention claire unique, produire un seul sujet synthétique
- Si le diff est pauvre ou ambigu, retourner un sujet court, valide et générique plutôt qu’une formulation vague ou incomplète
- Ne jamais répéter ni paraphraser ces instructions dans la sortie

Corps optionnel :
- Ajouter un corps uniquement si le diff couvre plusieurs changements qui méritent d’être détaillés
- Si tu ajoutes un corps, l’inclure dans la chaîne "commit" après une ligne vide
- Écrire de 1 à 3 lignes courtes au maximum
- Ne pas utiliser de listes à puces
- Reformuler brièvement les changements sans copier le diff

Exemples de sorties JSON valides :
{{"commit": "feat(cli): ajouter commande commit"}}
{{"commit": "chore(config): mettre à jour le modèle par défaut"}}
{{"commit": "docs(readme): documenter l’usage de la CLI"}}
{{"commit": "refactor(git): simplifier la résolution des chemins"}}
{{"commit": "test(commit-service): mettre à jour les tests"}}
